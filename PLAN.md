# CharLink v1 overnight plan (Nov 16–17, 2026)

Source brief: project doc `claude/fable-overnight-build-brief-nov16.md`. Independent build: no Atlas data.

## Decisions made without the owner (he is asleep)

| # | Decision | Why |
|---|---|---|
| 1 | **No Prisma/SQLite tonight. State lives in a browser store** (`lib/store`), seeded from versioned JSON in `data/`, persisted to localStorage with an in-memory fallback, and resettable from the header. | The brief allows a "read-mostly demo mode". SQLite does not persist on Vercel's serverless filesystem, and the demo must run with zero env vars. All domain logic is pure TypeScript, so moving to Postgres later means swapping the store, not the engines. |
| 2 | **Entity pages use query params** (`/lot?id=…`, `/quote?id=…`, `/order?id=…`) instead of `/lots/[id]`. | Buyers create RFQs, quotes and orders at runtime; query-param pages work on Vercel and in a static export (the fallback demo link). |
| 3 | **Keep the existing hand-written CSS system** instead of adding Tailwind/shadcn. | v0.1 already has a clean design language; extending it is faster and keeps one look. |
| 4 | **Documents are print-ready HTML pages** (`/doc?type=…`), saved as PDF with the browser's print dialog. | No PDF library needed, works offline and in the static export. |
| 5 | **Charts are small inline SVG components.** | Avoids a chart dependency for two chart types. |
| 6 | Server API routes are **stateless** (routing matrix, route geometry, match, quote, dataset reads). | State is in the browser; APIs expose the engines and data. |
| 7 | Stripe/Resend/NextAuth are **interfaces with mock defaults**; real adapters are thin server routes switched on by env vars and are untested without keys. | Zero-key rule; no sign-ups allowed tonight. |

## Architecture

```
data/            versioned JSON: producers, buyers, partners (researched tonight, every record sourced)
                 demo-lots.json and demo-scenarios.json (DEMO, generated by scripts/build-data.ts)
config/          assumptions.ts, grades.ts, applications.ts, property-ranges.ts (each value has a source note)
lib/domain/      types.ts, units.ts
lib/match/       sizePath, hard filters, weighted scoring, aggregation, closer-source swap
lib/logistics/   geo, freight (cube-out, FTL/LTL/parcel/van), landed-cost quote, CO2
lib/orders/      state machine, payments math (deposit, balance, payout, fee)
lib/credits/     CO2e estimate, registry eligibility
lib/providers/   routing, email, payments, storage, geocode: mock default + env-switched real adapter
lib/store/       client store (localStorage), seed, actions, notifications, outbox
app/             pages (below) + stateless API routes
tests/           vitest unit tests; e2e/ Playwright buyer journey + screenshots
docs/            DEMO_SCRIPT.md, MORNING_REPORT.md, COMPARISON_ATLAS.md, screenshots/
```

## Data model (see `lib/domain/types.ts`)

Organization (producer / buyer / partner) with sites, products, provenance fields and a data-gap score. Lot with per-value verification. RFQ, Match, Quote (options + line items), Order (state machine events, payments, shipment, documents), Message, Notification, OutboxEmail, ServiceSite/Unit/Visit, SpentMediaBatch, HubInventory, FinishingJob.

## Stages

0 plan → 1 dataset + configs → 2 engines + tests → 3 buyer flow → 4 orders/payments/docs/messages → 5 producer/ops/hub/service/credits → 6 map/library/grades/pricing/landing/impact → 7 e2e, screenshots, deploy, PR, Atlas comparison, report.

Floor if time runs short: Tier A + producer portal + ops console + deploy + report.

## Risks

- Dataset size: 100+ sourced producers in one night depends on what public pages show. The real count is reported; nothing is padded.
- Grade thresholds: only sourced numbers get values; the rest are marked TBD.
- Vercel preview: depends on the repo being connected. Fallback is a static export published as a private artifact.
